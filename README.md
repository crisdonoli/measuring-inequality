# Wealth Inequality in Chile — Methods in Practice

An applied, reusable codebase that shows how wealth inequality is estimated in practice,
from raw microdata to tail-corrected top shares:

1. clean a household survey and build a net-wealth variable,
2. compute survey-weighted percentile shares (bottom 50%, top 10%, top 1%),
3. correct the missing upper tail with the semi-parametric Pareto method of
   Vermeulen (2018), combining the survey with a rich list and anchoring financial
   assets to the National Accounts,
4. *(planned)* correct the whole distribution with the Blanchet–Flores–Morgan (2022)
   "merging point" method using tax tabulations,
5. *(planned)* replicate the same exercise on a second, independent survey (CASEN).

Each step is a self-contained notebook plus a function in `source/`, so the pieces can be
reused on other countries, years or surveys. The sequence of steps mirrors the
inequality problems in `documents/PS1_FPA.pdf`; it is not tied to that assignment.

## Requirements

- Python >= 3.10 with `pandas`, `numpy`, `matplotlib`, `pyarrow`, `fastparquet`,
  `openpyxl`, `jupyter` (only `matplotlib`, `fastparquet`, `pyarrow` and `pandas` are
  currently listed in `requirements.txt`).
- A LaTeX distribution with `latexmk`. All figures are compiled with
  `text.usetex = True` (`source/__init__.py`), so `pdflatex` must be on `PATH`;
  without it the plotting cells fail.

```bash
pip install -r requirements.txt
```

## Usage

Run the notebooks **in order** from inside `notebooks/` (`from utils import load_root`
relies on the working directory, and `load_root()` walks up to the directory containing
both `source/` and `data/`):

```bash
cd notebooks
jupyter lab          # or: jupyter notebook
```

### 1. `01_efh_cleaning.ipynb` — survey to net wealth

Loads `data/EFH/Base imputada EFH 2021.dta`, drops rows with missing `act_toth`,
`d_toth` or `factor`, and builds

```
net_wealth = act_fin + cap_pen_ent + (act_vp + act_otp + act_vehic + act_otros) - d_toth
```

Outputs `data/processed/efh_2021_clean.{csv,parquet}` and `figures/netwealth-efh.pdf`
(weighted vs. unweighted density, share of total wealth by bin).

### 2. `02_forbes.ipynb` — the rich list

Filters Chilean entries from the Forbes 2021 CSV, parses `NetWorth` (`'$17.7 B'` → `17.7`)
and converts to CLP at **759.1 CLP/USD**.
Outputs `data/processed/forbes_2021_clp.{csv,parquet}` and `figures/billionaires.pdf`.

### 3. `03_wealth_inequality.ipynb` — shares from the survey alone

Baseline: survey-weighted bottom-50 / top-10 / top-1 wealth shares
(`source.shares.weighted_shares`). This is the benchmark any correction has to beat.
Outputs `figures/p2/share.pdf`.

### 4. `04_vermeulen.ipynb` — Pareto tail correction

- estimates the Pareto tail index `alpha` above `w_min` with two methods: weighted MLE
  and the Gabaix–Ibragimov rank regression (`estimate_alpha_pareto`);
- shows sensitivity of `alpha` to `w_min` ∈ {380 M, 759.1 M, empirical p99}
  (`alpha_sensitivity.pdf`, `pareto_qq.pdf`);
- uprates `act_fin` so that the survey total matches the National Accounts financial
  assets aggregate, `426,112.5039` billions of CLP (`λ` = macro/survey);
- fills the gap between the richest EFH household and the poorest billionaire with
  conditional Pareto draws (`generate_pareto`, `seed=0`) and appends the Forbes
  observations (`vermeulen_correction`, final `alpha` from `w_min = 380 M`, MLE);
- reports raw vs. corrected shares and plots `shares_vermeulen.pdf`,
  `vermeulen_tail.pdf`.

## Method notes and caveats

- **Weights matter**: every share uses the survey weight `factor`; the denominator is the
  weighted sum of net wealth, so negative net wealth offsets positive holdings
  (see the report for why the Gini is unreliable in this case).
- **`w_min = 380 M CLP`** is not estimated: it is the threshold giving the best Pareto QQ
  fit and is hard-coded in notebook 04. `759.1 M` corresponds to the poorest Forbes
  billionaire (1 B USD at the 759.1 CLP/USD rate).
- **Hard-coded constants**: FX rate `759.1` (notebook 02) and the National Accounts
  financial-asset aggregate `426112.5039` bn CLP (notebook 04). Changing the data sources
  implies editing these values by hand.
- **Re-running notebook 04 mutates `efh_df`** (`act_fin` uprated, `net_wealth` recomputed
  as `act_toth - d_toth`). The uprating cell reloads the clean parquet when it detects a
  `λ` near 1 to avoid double counting, but after a full run re-execute the *Data load*
  cell before re-running downstream cells.
- Pareto draws are seeded (`seed=0`), but the correction is a simulation: shares move
  slightly if the row order or the number of draws changes.
- Raw inputs are not regenerated by the pipeline; `data/EFH/` and `data/Forbes/` must be
  obtained from their original sources (links in the notebooks).
